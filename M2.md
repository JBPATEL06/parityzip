# M2 - Compress

Branch: `m2-compress` from `main` (M1 merged). Read `docs/PROJECT.md`, the project rules, and the skills `par2-7z-cli-wrapper`, `flutter-linux-desktop`, `yaru-ui-guidelines`, `milestone-verification`.

## Scope
Make the **Protect** tab create a `.7z` archive. Recovery data (par2) is NOT part of M2; the slider and par2 are M3.

### 0. Spikes first (before any feature code)
Run on this machine, on scratch data under `/tmp`, and write findings to `docs/spikes/7z-switches.md`:
1. Which 7z binary is used (`7zz`/`7z`/`7za`) and its version line.
2. Does `-bsp1` print progress to stdout? Paste a captured sample (including the `\r` behaviour).
3. Is `-spd` accepted? Does a file named `star*.txt` and `bracket[1].txt` archive correctly with and without it?
4. Symlinks: archive a symlink-to-file and a symlink-to-folder with and without `-snl`; extract and report what each produces (link or copied content or error). Recommend one behaviour.
5. How are absolute vs relative input paths stored (`7z l`)? Confirm that using `workingDirectory` + relative names stores clean paths.
6. How is a name starting with `-` handled with `./name`? Show `7z l`.
7. Exit codes seen for: success, a missing input file, an unreadable file (chmod 000).
Stop and report if any result contradicts the `par2-7z-cli-wrapper` skill. Do not guess.

### 1. Core logic (pure Dart, unit tested)
- `SevenZipService.buildCreateArgs({level, outputFileName, names})` -> argument list for `7z a -t7z -mx=<1|5|9> -bsp1 ...` (plus `-spd` / `-snl` only if the spike recommends them).
- `InputSelection` validation: all items share one parent folder; at least one item; output folder is not inside a selected folder; output file `<outputDir>/<name>.7z` must NOT already exist; name is non-empty, contains no `/` or NUL, `.7z` appended once.
- Progress parser (`(\d{1,3})%`, split on `\r` and `\n`) tested with real captured output from the spike.
- Exit-code mapper: 0 success; 1 success with warnings (show them); 2 and other codes failure; 255 cancelled.

### 2. Job execution
- `JobController` runs the job through `ProcessRunner`, streams log lines, updates progress, supports Cancel.
- Cancel: kill the process, delete ONLY the partial output file this job created, return to idle with a "Cancelled" note.
- Close stdin immediately (no password in M2).

### 3. UI (Protect tab)
Per `yaru-ui-guidelines`: drop zone + "Add files" + "Add folder" (`file_selector`, `desktop_drop`), selected-items list with remove buttons, output folder chooser, archive name field, level selector (Fast / Normal / Maximum, default Normal), "Create archive" button, progress card with Cancel, result card (output path, archive size, warnings) with "Open folder" (`xdg-open`, argument list). Button disabled with an explanation when validation fails or `7z` is missing. Leave a clearly marked, disabled "Recovery data" section reading "Coming in M3".

### 4. Fixtures
Create `tool/make_fixtures.sh` (output to `/tmp/parityzip-fixtures`, never into the repo): `small.txt`, `random_10MB.bin`, nested folders, `rapport été.txt`, `ફાઇલ.txt`, `with space.txt`, `-odd.txt`, `star*.txt`, `bracket[1].txt`, `hub_lite` and `hub_LITE`, symlink to a file, symlink to a folder. Option `--big` also creates `random_500MB.bin`.

## Out of scope
