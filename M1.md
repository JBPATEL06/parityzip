# M1 - Skeleton and tool detection

Branch: `m1-skeleton`. Read `docs/PROJECT.md`, the project rules, and the skills `flutter-linux-desktop`, `yaru-ui-guidelines`, `par2-7z-cli-wrapper` (discovery section only), `milestone-verification`.

## Scope
1. In the repo root run `flutter create --platforms=linux --project-name parityzip .` (the folder already contains `.agents/` and `docs/`; keep them).
2. Add dependencies: `yaru`, `provider`. Nothing else.
3. App shell: window title "ParityZip", Yaru theme (light/dark follows system), three tabs: Protect, Verify, Repair. Each tab shows a placeholder text ("Coming in M2" / "M4" / "M4") and the shared log panel widget.
4. `ToolLocator` (pure Dart, injectable PATH string and file-check function for tests): finds the first available of `7zz`, `7z`, `7za`, and `par2` on PATH. Returns a `ToolStatus` with found/missing and path.
5. `tool_banner` widget: if any tool is missing, show a dismissible banner naming the missing tool(s) and the text `sudo apt install p7zip-full par2` with a Copy button. No banner when both are found.
6. `ProcessRunner` abstraction + `RealProcessRunner` + `FakeProcessRunner` (for tests). No tool is executed in M1 beyond what tests need.
7. `log_panel` widget: collapsed by default, monospace, selectable, Copy log button, capped at 5000 lines.
8. `.gitignore` suitable for Flutter. A short `README.md` for the app (what it is, status "in development", prerequisites). Do NOT add a LICENSE file.

## Out of scope
Any compression, par2, file picking, drag-and-drop, packaging.
