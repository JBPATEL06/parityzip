# M3 - Recovery data (PAR2 create)

Branch: `m3-recovery-data` from `main` (M2 merged and tagged `m2`). Read `docs/PROJECT.md`, the project rules, and the skills `par2-7z-cli-wrapper`, `flutter-linux-desktop`, `yaru-ui-guidelines`, `milestone-verification`.

## Scope
After the archive is created, optionally create PAR2 recovery data next to it, then run a quick `par2 verify` as a sanity check. The Protect tab becomes a three-step job: **1. Compress -> 2. Create recovery data -> 3. Check recovery data**. Verify/Repair tabs stay placeholders (M4). The par2 code must not depend on the archive format (7z today, ZIP may come later): it works on "any file".

Stop and report if any result contradicts the `par2-7z-cli-wrapper` skill. Do not guess.

### 1. Core logic (pure Dart, unit tested)
- `Par2Service.buildCreateArgs({redundancy, archiveFileName})` -> argument list (`create`, `-r<N>`, `<archive>.par2`, `<archive>`), using the `./` prefix form if the name starts with `-` (as the spike confirms).
- Validation: redundancy integer 5-30 (default 10); archive file exists; none of `<archive>.par2` or `<archive>.vol*.par2` already exist (refuse, name the conflicting file, touch nothing).
- Progress parser using real samples from the spike.
- Exit-code mapper for `create` (0 success, everything else failure with the spike's meaning).
- `Par2Service.buildVerifyArgs(par2FileName)` for the post-check only (M4 will reuse it).
- Pipeline controller: runs steps 1-3 in order, reports step index/label, stops at the first failing step.

### 2. Cancel and failure rules
- Cancel in step 1: as in M2.
- Cancel or failure in step 2: kill the process, delete ONLY the `.par2` files this job created (compare the folder listing before and after), KEEP the finished archive, and tell the user clearly that the archive exists without recovery data.
- Failure in step 3 (post-check fails): keep everything, show a warning "Recovery data could not be verified" with the log. Never delete anything.

### 3. UI (Protect tab)
Enable the "Recovery data" section: a switch "Create recovery data" (default on) and a slider 5-30 (step 1, default 10) with label "Recovery data: 10%" and hint "Roughly this much damage can be repaired". Show the estimated extra size only if the spike shows it can be computed reliably; otherwise omit. Progress card shows "Step 2 of 3: Creating recovery data" with its own bar and a Cancel button. Result card lists the archive, the number of `.par2` files, their total size, overhead percent, and the sanity-check result, plus "Open folder". If `par2` is missing: the switch is off and disabled with an explanation; compression still works when 7z is present. If `7z` is missing the existing M2 behaviour stays.

## Out of scope
Protecting an already existing file, Verify and Repair tabs (M4), encryption (M5), ZIP output, packaging.
