# M5 - Encryption (7z only)

Branch: `m5-encryption` from `main` (M2b merged and tagged `m2b`). Read `docs/PROJECT.md`, the project rules, and the skills `par2-7z-cli-wrapper` (Encryption section), `flutter-linux-desktop`, `yaru-ui-guidelines`, `milestone-verification`.

## Why this milestone is risky
A password given to a command-line tool as `-p<password>` can be read by any local user through `ps` and `/proc/<pid>/cmdline`. The password must reach 7z through stdin only, and must never be logged, written to disk, or put in arguments or environment variables. If stdin cannot be made reliable, we stop and ship without encryption. We do NOT fall back to the argument form.

## Scope

### 0. Spike and decision gate (before any feature code)
On scratch data under `/tmp`, with `timeout 60` on every command so nothing can hang. Write findings to `docs/spikes/stdin-password.md` with real captured output:
1. Does `7z a -t7z -mhe=on -p <out.7z> <file>` read the password from a pipe (no terminal)? How many lines does it read when CREATING (enter and verify)? What happens with one line, with two lines, with zero (closed stdin)?
2. Same test with no controlling terminal at all (e.g. `setsid -w sh -c '...'`), because the app is launched from a desktop menu without a TTY. Does it still work, or does 7z try to open `/dev/tty`?
3. `7z t -p <archive>` and `7z x -p <archive>` with piped password: how many lines, what output on success.
4. Wrong password: exit code, message, and whether it can hang when stdin is closed.
5. `-mhe=on` effect: `7z l <archive>` without a password must not reveal file names. Paste the output.
6. Method check: `7z l -slt <archive>` output showing the encryption method. Only claim "AES-256" in the UI if this output confirms it.
7. Password edge cases through stdin: spaces, unicode (e.g. `Tést Pass ફા 123!`), leading dash, quotes, backslash, 200 characters. Does the UTF-8 round trip work regardless of the locale (try `LANG=C`)?
8. While a job on a 500MB file runs, capture `ps -eo pid,args | grep 7z` and `tr '\0' ' ' < /proc/<pid>/cmdline`. The password must not appear.
9. Exit codes for success, wrong password, missing input.
10. Alternatives, documentation only (do not implement): list other ways the installed 7z could receive a password without argv, with their exposure.
**Decision gate:** end the spike document with `DECISION: stdin approach supported` or `DECISION: not supported`. If NOT supported, or if it only works with a terminal, STOP and report to Jeel. Do not implement anything else.

### 1. Core logic (pure Dart, unit tested)
- `PasswordPolicy`: minimum 8 characters, no newline or NUL, password and confirmation must match. Returns specific, plain-English reasons.
- `SevenZipService.buildCreateArgs` with `encrypt: true` adds `-mhe=on` and a bare `-p` (exactly as the spike confirms). The password is NEVER part of the argument list.
- Password delivery: bytes written to the process stdin in the exact line format found by the spike, then stdin closed. Extend `ProcessRunner` so `stdinData` is a `Uint8List`; the runner must never log it. After writing, zero the byte list.
- `SevenZipService.buildTestArgs` for `7z t -p` (password via stdin) used as a final "Checking archive" step for encrypted jobs.
- Log redaction: any log line that contains the password string is replaced with `***` before it reaches the log panel or "Copy log". Test it.
- Gating: encryption allowed only when the format is 7z. ZIP + encrypt is rejected in the controller as well as the UI.
- Pipeline for encrypted jobs: 1 Compress (encrypted) -> 2 Recovery data (needs no password; it works on the finished file) -> 3 Check recovery data -> 4 Check archive with password (`7z t`). Step 4 failing (for example a wrong password typed twice the same) keeps the files and shows a clear warning.
- Lifetime: the password lives only in the form fields and the job's byte list; clear the fields and the bytes when the job ends, fails, or is cancelled. Do not store it in any controller field that outlives the job. Dart strings cannot be wiped from memory; document this limitation honestly in the README.

### 2. UI (Protect tab, 7z only)
Section "Encryption": switch "Protect with a password" (default off); password field and confirm field with show/hide toggles; a one-line length hint; text "File names are hidden too"; a required checkbox "I understand that a lost password cannot be recovered" (Create stays disabled until ticked); disabled with a clear explanation when ZIP is selected. Create-button disabled with a reason when the policy fails. Result card for encrypted jobs: "Encrypted" plus a note "Open it with 7-Zip or another tool that supports 7z with passwords". Show "AES-256" only if the spike confirmed it. The fields are cleared after every job outcome.

## Out of scope
Decrypt/extract UI, key files, ZIP encryption, password managers, guaranteed memory wiping, packaging.
