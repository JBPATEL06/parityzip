### 1. App changes

Add `package_info_plus` for the version only if needed. No password or file names anywhere in it.

### 2. Release build: `tool/build_release.sh`
- `set -euo pipefail`. Refuses to run with a dirty git tree or off a tag/branch rules Jeel sets in `docs/RELEASING.md`.
- Runs `flutter clean`, `flutter pub get`, `flutter analyze`, `flutter test`, `flutter build linux --release`.
- Checks that the version in `pubspec.yaml`, the `PARITYZIP_VERSION` constant in `install.sh`, and `CHANGELOG.md` agree; fails otherwise.
- Produces in `dist/`: `parityzip-<version>-linux-x64.tar.gz` (the bundle contents under a single top folder `parityzip-<version>/`, plus `install-data/` with the desktop file, icons, `uninstall.sh`, `LICENSE`) and `parityzip-<version>-linux-x64.tar.gz.sha256`.
- Prints the exact commands Jeel runs to publish the GitHub Release. The script itself never pushes, tags or uploads.

### 3. `install.sh`
Requirements (read `linux-packaging-install`): `#!/usr/bin/env bash`, `set -euo pipefail`, shellcheck clean, readable and commented, prints every step. Concretely:
- Constant `PARITYZIP_VERSION="v0.1.0"` (pinned; never downloads "latest" or `main`). Downloads `parityzip-<version>-linux-x64.tar.gz` and its `.sha256` from the GitHub Release of that tag, verifies the checksum, aborts on mismatch before touching the system.
- Options: `--yes` (auto-confirm package installation), `--no-deps`, `--dry-run` (print every action, change nothing), `--local <dir>` (use a tarball and checksum from a local folder instead of downloading, for testing before the release exists).
- Installs for the current user only: app to `~/.local/share/parityzip/` (written to a temp folder next to it, then swapped in so a failed install never leaves a half install), symlink `~/.local/bin/parityzip`, desktop file `~/.local/share/applications/<app-id>.desktop`, icons under `~/.local/share/icons/hicolor/...`. Writes a marker file and a `VERSION` file inside the install folder and copies `uninstall.sh` there.
- If `~/.local/bin` is not on `PATH`, print a clear note (menu launch still works).
- Dependencies: detect the package manager. `apt` is implemented and tested. `dnf` and `pacman` are implemented from the spike's findings and labelled "untested" in output and README unless actually verified. Choose the package names per the spike (for example prefer a package that provides the binaries the app finds). Before using `sudo`: ask for confirmation, reading the answer from `/dev/tty`; if there is no terminal and no `--yes`, do NOT use sudo, print the exact command and continue (the app also shows a banner when a tool is missing). Check `ldd` on the installed executable and warn about any missing system library with the package to install.
- Idempotent: running it again upgrades cleanly (same result, no duplicates). Safety: never delete anything unless the path equals the exact expected install folder AND contains the marker file; use `${VAR:?}` guards; never touch files outside `~/.local/share/parityzip`, the symlink, the desktop file and the icon files this script created.
- Runs `desktop-file-validate` if available and refreshes the desktop database/icon cache when the commands exist.

### 4. `uninstall.sh`
Removes only what `install.sh` created (install folder with marker, symlink if it points there, desktop file, icons), in that safe manner; supports `--dry-run`; does not remove the helper tools (`7z`, `par2`) and says so; never touches user data.

### 5. Documentation
- `README.md` (user-facing): what it is, features (compress 7z/ZIP, recovery data, verify, repair, 7z encryption), screenshots placeholder, the install command `curl -fsSL https://raw.githubusercontent.com/<user>/<repo>/v0.1.0/install.sh | bash` and a "download and read it first" alternative, requirements, manual install, uninstall, how recovery data files work (separate `.par2` files next to the archive), honest limitations (separate par2 files not embedded; encryption 7z only; no password recovery; ZIP behaviour on Windows/macOS not yet tested by the maintainer; `dnf`/`pacman` support untested if so), privacy statement (no network access, no telemetry), licence.
- `LICENSE` (standard text for `LICENCE`) and a short third-party notice: 7-Zip and par2cmdline are separate programs installed from the distribution, not bundled.
- `CHANGELOG.md` with the v0.1.0 entry; `docs/RELEASING.md` with the exact manual steps for Jeel (build, test on a clean VM, tag `v0.1.0`, create the GitHub Release, upload the two files, verify the install command from a clean machine).
- Never claim in README something that no test in this milestone proved.
